When a competitor's trial record changes, an Agent finds out why and writes a sourced brief

Built for pharma competitive-intelligence and commercial-analytics teams. The watchlist refreshes from ClinicalTrials.gov every day. When a registry record changes, the Agent decides for itself which public sources to check (company announcements, investor materials, regulatory filings and more) and writes a four-part brief: What happened / What sources say / What is still unclear / Analyst view. Every fact links to its source; if nothing explains the change, the brief says "Evidence insufficient".

Current focus: obesity / weight-loss drugs · Phase 2 and 3 trials from Lilly, Novo Nordisk, Amgen and AstraZeneca

How it works

Each step is marked as automated, done by the Agent, or done by hand
01WatchlistPick a therapeutic area and the competitors' key trialsManual
02Daily refreshGitHub Actions pulls every trial from the ClinicalTrials.gov API each day and saves a snapshotAutomated
03Detect changesCompare old and new versions to find meaningful field changes. In the alpha this is done by hand from the record history; next, SQL over the daily snapshotsManual → SQL
04InvestigateThe Agent chooses what to search and which sources to open, and only uses sources that mention the trial or drugAgent
05Write the briefFour parts + source table + search log; inferences labeled; "Evidence insufficient" when nothing explains the changeAgent
06Human reviewEvery claim is marked correct / wrong / no source found, and the findings feed back into the instructionManual
Key rules in Agent instruction v0
  • Open the record history first and confirm the change; flag any mismatch with the input at the top
  • Only use sources it actually opened that mention this trial or drug
  • Every sentence in parts 1 and 2 needs a link; inferences go only in part 4, each starting with [Inference]
  • Never invent a URL, quote, number or date; if unsure, leave it out
  • "Evidence insufficient" is an acceptable answer; never guess a reason to fill the gap
  • List every search query used, so the work can be checked

Alpha evaluation

Goal of this version: given a real registry change, the Agent finds sources on its own, writes a linked brief, and the brief holds up under review

Early observations ⚠ sources not yet verified

  1. Format and honesty held up: all 3 runs used the four-part format, linked their facts and labeled inferences separately; none found an explanation, and all said "Evidence insufficient" instead of guessing.
  2. Stable conclusion, unstable path: running the same change twice gave the same conclusion, but only 1 cited source overlapped.
  3. Filler sources: the Agent cites sources that mention the drug but do not explain this change.
  4. Names not in the input: the Agent introduced "zenagamtide" and "REDEFINE 11". A first check suggests both match; pending human review.
  5. Possibly missed a relevant source: a Feb 2026 Novo Nordisk announcement expects REDEFINE 11 data in 1H 2027, consistent with change #3's new date; the Agent did not cite it.

Known limitations

  • Briefs are generated offline: the Agent runs in ChatGPT (with web search) under the instruction, and the results are then published here. The site cannot trigger the Agent yet.
  • Only 3 development cases so far, all "Evidence insufficient"; cases where a cause can be found are not tested yet.
  • No accuracy figure yet; that comes after the claim-by-claim review.
