面向药企竞争情报和商业分析团队。系统每天从 ClinicalTrials.gov 更新关注名单；发现登记信息变化后，由 Agent 自己决定去查哪些公开来源（公司公告、投资者材料、监管文件等），按四段写成简报：发生了什么 / 来源怎么说 / 还不清楚什么 / 分析判断。每条事实附链接，查不到就写“证据不足”。

工作原理

标出每一步目前是自动、Agent 还是人工
01关注名单选定领域和竞品关键试验人工
02每日更新GitHub Actions 每天从 ClinicalTrials.gov API 拉取，保存快照自动
03发现变化对比新旧版本，找出有意义的字段变化。Alpha 用变更历史手动找；之后用 SQL 对比每日快照人工 → SQL
04调查原因Agent 自己决定搜什么、打开哪些来源，只用提到该试验或药物的来源Agent
05写成简报四段式 + 来源表 + 搜索记录；推断单独标注；查不到写“证据不足”Agent
06人工核对每条说法标 对 / 错 / 找不到来源，用来改进指令人工
Agent 指令 v0 的关键规则
  • 先打开变更历史，确认变化本身；与输入不符要在开头说明
  • 只用真正打开过、并且提到这个试验或药物的来源
  • 第 1、2 段每句话都要有链接；推断只能放第 4 段，句首标 [Inference]
  • 不许编造网址、引语、数字或日期；不确定就不写
  • “证据不足”是可接受的答案，不许为了填空去猜原因
  • 列出所有用过的搜索词，方便复查

Alpha 评测

这一版要证明：给一个真实变化，Agent 能自己找来源、写出带链接的简报，并经得起核对

早期观察 ⚠ 未核对来源

  1. 格式和诚实度达标：3 次运行都按四段输出，事实附链接，推断单独标注；没找到解释时都写了“证据不足”。
  2. 结论稳定，路径不稳定：同一变化跑两次，结论相同，引用来源只重合 1 个。
  3. “凑数来源”：会列出只提到药物、却不能解释这次变化的来源。
  4. 引入输入里没有的名字：zenagamtide、REDEFINE 11。初步查证两个都对得上，待人工复核。
  5. 可能漏掉相关来源：Novo 2026-02 的公告提到 REDEFINE 11 预计 2027 上半年出数据，与变化 #3 的新日期一致，Agent 未引用。

核对进度与下一步

  • 进行中 逐条核对 Agent 的每句说法（对 / 错 / 找不到）
  • 待做 人工手写变化 #1 的简报，作为对照基准
  • 待做 根据问题把指令改成 v1，重跑并比较
  • 之后 扩到 15–20 个真实变化；开发案例和评测案例分开
  • 之后 三组公平对比：只用登记信息 / 固定检索流程 / Agent
  • 之后 业内人士盲评三组输出

已知局限

  • 简报目前是离线生成：Agent 在 ChatGPT（开网页搜索）里按指令运行，结果再放到网站上；网站本身还不能一键触发 Agent。
  • 只有 3 个开发案例，且都是“证据不足”，还没测到“能查到原因”的情况。
  • 还不能报告准确率，要等逐条核对完成。
